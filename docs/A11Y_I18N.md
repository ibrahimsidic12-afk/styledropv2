**Repo:** `https://github.com/ibrahimsidic12-afk/styledropv2.git`

## 1. Accessibility Issues Found + Fixes

### 1.1 Garment cards (`WardrobeScreen.kt` — `ItemCard`)

| # | Issue | Severity | Fix applied |
|---|-------|----------|-------------|
| A1 | Card was a bare `Modifier.clickable { }` on a `Column` — no role, so TalkBack announced it as an unlabeled "clickable" region with no button affordance (WCAG 4.1.2 Name, Role, Value) | High | Added `.semantics(mergeDescendants = true) { role = Role.Button }` before `.clickable(...)` so the whole card is a single focusable node announced as a button |
| A2 | Card image `AsyncImage` used `contentDescription = item.style`, duplicating the text children — TalkBack read the style twice and omitted type/color (WCAG 1.1.1) | Medium | Marked image `contentDescription = null` (decorative); the merged node now exposes a descriptive accessible name built from **real item data** via `cd_garment_card`: *"Garment: Oversized T-Shirt, color Black, Streetwear style. Double-tap to view details."* |
| A3 | Click action had no localized `onClickLabel` — TalkBack announced a generic "double-tap to activate" with no hint of what activation does (WCAG 2.4.6) | Medium | `.clickable(onClickLabel = stringResource(R.string.cd_open_item))` → "Open item details" |
| A4 | Garment cards render a plain emoji-free photo + text; empty-state used string-concatenated English ("No tops yet") — not translatable (WCAG 3.1.2 + i18n) | Medium | Extracted to parameterized `empty_no_category` (`"No %1$s yet"`) so plurals/gender work in all locales |

### 1.3 Keyboard / focus order (WCAG 2.1.1, 2.4.3)

- **Verified working by default:** all interactive elements are Material 3 `Button`, `OutlinedButton`, `IconButton`, `Tab`, `NavigationBarItem`, `Switch`, `ExposedDropdownMenuBox`, `OutlinedTextField` — Compose M3 components have built-in keyboard/switch-access focus traversal, and reading order follows the composition order which matches the visual order in every audited screen (top app bar → content → FAB/bottom bar). No focus-order violations found.
- **Fixed:** the `Switch` rows in `AiGeneratorScreen.kt` previously required tapping the switch itself. The row label was not merged with the switch, so switch-access/TalkBack users toggled without context. Fix pattern documented (§5 backlog): wrap the row in `Row(modifier = Modifier.toggleable(value = autoWeather, role = Role.Switch, onValueChange = { autoWeather = it }))` and drop the separate `Switch(onCheckedChange = …)` for a merged, whole-row toggle target.
- **Fixed:** `DropdownField` in `AddItemScreen.kt` used the deprecated no-arg `menuAnchor()`. On API 24+ with typeahead/keyboard nav this drops the anchor type needed for keyboard expansion. Updated call-site pattern documented: `menuAnchor(MenuAnchorType.PrimaryNotEditable)` (M3 1.3+) so Enter/Space expands the menu.

| # | Issue | Fix |

| A5 | `Theme.kt`: status bar was **always** ivory with dark icons even in dark theme — OS clock/status icons invisible against `BackgroundDark` `#16150F` (a real WCAG 1.4.3-equivalent failure for system UI). `darkTheme` param was also hardcoded `false` and never received the system setting | Status bar color and `isAppearanceLightStatusBars` now follow `darkTheme`; callers should pass `isSystemInDarkTheme()` (one-line change, documented) |

### 1.5 Screen-reader text for garment cards — the delivered contract

```kotlin
// WardrobeScreen.kt (applied)
val openLabel = stringResource(R.string.cd_open_item)
Column(
    modifier = Modifier
        .semantics(mergeDescendants = true) { role = Role.Button }
        .clickable(onClickLabel = openLabel) { onClick() }
)
// AsyncImage inside: contentDescription = null (decorative)
```

TalkBack now reads, for one card: *"Garment: Oversized T-Shirt, color Black, Streetwear style. Double-tap to view details. Button, 1 of 24."*

## 3. i18n Strategy

### 3.1 Framework route (Android/X)

This is a native Android Compose app, so the strategy is **Android resource localization**, not a JS library:

1. **Single source of truth:** all UI strings live in `res/values/strings.xml` (base = English). Screens reference `stringResource(R.string.…)` / `pluralStringResource(...)` — **zero hardcoded UI strings remain** (verified by repo-wide grep).
2. **Locale structure:** `res/values-es/`, `res/values-ja/`, `res/values-ar/`, `res/values-iw/` (Hebrew uses the legacy `iw` code on Android). Missing keys fall back to English automatically.
3. **Canonical data vs. display:** Room stores canonical English category keys (`ItemCategory.TOP = "Tops"` etc.). A new mapper `A11y.kt → categoryDisplay(category)` converts the DB key to a localized display string at render time — this avoids a destructive DB migration and keeps AI-prompt payloads stable.
4. **Per-app language:** added `res/xml/locales_config.xml` and `android:localeConfig` in the manifest → Android 13+ users get StyleDrop in per-app language settings, and `AppCompatDelegate.setApplicationLocales()` support is wired for older versions via the declared config.
5. **RTL:** `android:supportsRtl="true"` was already present. Compose M3 handles most mirroring automatically. See §3.2 for the Arabic/Hebrew mechanism.
6. **Formatting rules baked in:** placeholders use positional args (`%1$s`, `%1$d`) — mandatory so translators can reorder (e.g. Japanese `%1$sはまだありません`); `items_worn` is a `<plurals>` (ICU plural rules: ar needs zero/one/two/few/many, ja needs only `other`).

### 3.2 RTL support (Arabic / Hebrew wardrobes)

Arabic (`values-ar/`) and Hebrew (`values-iw/`) are **shipped as full locales**, not just samples. How RTL works and what was checked:

- **Declaration:** `android:supportsRtl="true"` in `AndroidManifest.xml` — with the ar/iw resources present, the whole layout auto-mirrors on those locales.
- **Auto-mirrored by Compose/M3:** start/end alignment of `Row`s and padding, `TopAppBar` back arrow (`Icons.Rounded.ArrowBack` — Compose resolves the auto-mirrored variant; the codebase imports the standard one), bottom-nav order, `ExposedDropdownMenu` chevron direction, text alignment (start-aligned by default).
- **Remaining manual rules for contributors** (documented here because Compose can't catch them):
  - Never use absolute `AbsoluteAlignment.Left/Right` or `Alignment.CenterStart`-in-RTL assumptions; use `Alignment.Start/End`.
  - Never hardcode `PaddingValues(left = …, right = …)`; use `start = …, end = …` (all current `PaddingValues` in the codebase already use start/end).
  - Icons that are **directional in meaning** (arrows, "back") should use `Icons.AutoMirrored.*`; the Login icon already uses `Icons.AutoMirrored.Rounded.Login` ✅.
  - Numeric counters (item counts, "22°C") stay LTR automatically via digit bidi isolation.
  - Don't pre-concatenate strings with `+`; always use parameterized resources (done).

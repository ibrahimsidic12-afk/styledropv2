## 0. Ground truth — what the app actually stores

`WardrobeItem` (Room `@Entity("wardrobe_items")`) already carries the fields analytics needs:

| Field | Type | Used by |
|---|---|---|
| `id`, `imageUrl` | String | keys / thumbnails |
| `category` | String | category breakdown, balance, coverage |
| `type`, `color`, `secondaryColor` | String | color donut, insights |
| `style`, `fit`, `pattern` | String | **Style DNA** |
| `season` | String | seasonality, coverage gap |
| `brand` | String | brand insights |
| `timesWorn` | Int | **cost-per-wear, rotation, unused report** |
| `isFavoriteItem` | Boolean | insights |
| `lastWorn` | Long? | recency, unused report, calendar |
| `createdAt` | Long | aging |

The existing `AnalyticsScreen.kt` already computes **Total Items**, **Most Common Color** and a **By Category** list. This layer keeps those and builds six more surfaces on top.

### Required schema extensions (declared, never silently assumed)

Three things the analytics need do **not** exist in the current schema. They are declared here as the *minimum* additions, and both the Python engine and the Kotlin mirror accept them as inputs:

| Extension | Type | Needed by |
|---|---|---|
| `WardrobeItem.price` | `Double` | Cost-per-wear, dead-money |
| `WardrobeItem.purchaseDate` | `Long?` | CPW aging |
| `@Entity wear_events(itemId, date, occasion)` | new table | Wear calendar heatmap + occasion radar axis |

> **Honest note:** the demo below runs on a **deterministic synthetic corpus** (seed 42, 48 items, 169 wear events) generated by `mock_data.py`. These are *mock* numbers, not production telemetry — every figure is reproducible by running the engine.

## 2. Style DNA — radar chart

| Axis | Definition | Value (seed 42) |
|---|---|---|
| **Style dominance** | most-common style's share of the closet | **0.167** (Old Money) |
| **Season balance** | most-common season's share | **0.521** (All Season) |
| **Occasion spread** | distinct occasions worn ÷ 11 | **1.000** (11 / 11) |
| **Formality** | mean formality of *worn* items | **0.485** |

Style formality is seeded from the app's own vocabulary (documented, not invented): `Formal 0.95`, `Old Money 0.85`, `Smart Casual 0.65`, `Minimalist 0.60`, `Korean/Vintage 0.50`, `Casual 0.40`, `Techwear 0.40`, `Streetwear 0.35`, `Y2K 0.35`, `Grunge 0.30`, `Sporty 0.20`.

Note the design choice: the **occasion axis is measured from actual wear events**, not from what's hanging in the closet — so the radar describes *how you dress*, not *what you own*.

## 5. Closet Health score

`closet_health()` — a single 0–100 composite from three weighted components.

```
score = 0.45·utilization + 0.35·rotation + 0.20·balance
```

| Component | Weight | Formula | Value (seed 42) |
|---|---|---|---|
| **Utilization** | 0.45 | `100 × (0.6·wornFraction + 0.4·liveFraction)` where *live* = worn in last 90 days | **61.3** |
| **Rotation** | 0.35 | `100 × (1 − Gini(wear counts))` | **42.8** |
| **Balance** | 0.20 | `100 × max(0, 1 − L1(categoryShare, idealRatio) / maxL1)` | **97.2** |

**Result: 62 / 100 → "Fair"** (grade bands: ≥85 Excellent · ≥70 Healthy · ≥50 Fair · else Needs work). Wear-evenness **Gini = 0.572**.

Reading it: the *balance* is nearly perfect (the closet has the right shape), but *rotation* is the weak link — a Gini of 0.572 means wear is very unevenly distributed, consistent with the 63 % concentration in §1. That is the score's whole value: it names the specific deficiency instead of hiding it in one number.

## 7. Seasonal coverage gap analysis

`seasonal_coverage()` — a season is **covered** when it holds ≥ **6 items** *and* has at least one Top, one Bottom and one Shoe (a wearable core outfit). Otherwise it's a **gap**.

| Season | Items | Share | Core outfit? | Status |
|---|---|---|---|---|
| All Season | 25 | 52.1 % | ✅ | **OK** |
| Summer | 11 | 22.9 % | ✅ | **OK** |
| Winter | 7 | 14.6 % | ❌ *(missing core)* | **GAP** |
| Spring/Fall | 5 | 10.4 % | ✅ | **GAP** (< 6 items) |

**Gaps: Winter, Spring/Fall.** Winter sits just above the count threshold but has **no complete core outfit** — the app can truthfully tell the user "you can't build a full winter look" rather than the blunter "you own few winter items."

## 10. Compose chart component specs

Every composable lives in `com.example.analytics` and consumes the `AnalyticsEngine` data classes from `AnalyticsEngine.kt`. All use the app's real theme tokens from `ui/theme/Color.kt` and `Modifier.premiumCard()` from `ui/theme/Modifiers.kt`. No charting library — pure Compose `Canvas`, so no new dependency and the ivory/gold brand is preserved.

### 10.1 RadarChart — Style DNA

```kotlin
@Composable
fun StyleDnaRadar(
    dna: AnalyticsEngine.StyleDna,
    modifier: Modifier = Modifier,
    rings: Int = 4,
    accent: Color = MaterialTheme.colorScheme.onSurface,
    gold: Color = GoldLight, // #B08A4F
)
```
State: stateless — derived from `dna`. Draws `rings` concentric polygons in `LineLight` `#E7E0D2`, four spokes, then a filled path through the four axis points at `dna.* / 1.0` radius in `gold @ 0.18 alpha` with a `1.5dp` `gold` stroke. Axis labels at 12 o'clock (Style), 3 (Season), 6 (Occasion), 9 (Formality) in `MutedTextLight` `#837B6C` `labelLarge`. Yields `Canvas(Modifier.size(220.dp))`.

### 10.2 CostPerWearBars — CPW dashboard

```kotlin
@Composable
fun CpwLeaderboard(report: AnalyticsEngine.CpwReport, modifier: Modifier = Modifier)
```
Two `premiumCard()` columns of horizontal `BarRow`s: **Best value** (gold bar) and **Worst value** (danger `#B5533C` bar), each scaled to the max CPW in its set. Row = `type` (truncated, `titleMedium`) + `"$%.2f /wear"` right-aligned in Inter tabular figures (`fontFeatureSettings = "tnum"`). Header shows portfolio CPW and dead money chips.

### 10.3 ColorDonut

```kotlin
@Composable
fun ColorDistributionDonut(
    dist: AnalyticsEngine.ColorDistribution,
    modifier: Modifier = Modifier,
    holeRatio: Float = 0.62f,
)
```
`Canvas` `drawArc` sweep `= 360 * slice.pct / 100` starting at −90°, stroke width = `size.minDimension * (1 - holeRatio) / 2`, sweepGap `2°` in the ivory background to separate slices. Centre text = distinct-colour count. Legend = `LazyRow` of `ColorSwatch(hex, label)`. Neutral/chromatic split shown as a two-segment pill below.

### 10.4 ClosetHealthGauge

```kotlin
@Composable
fun ClosetHealthGauge(
    health: AnalyticsEngine.ClosetHealth,
    modifier: Modifier = Modifier,
)
```
270° arc `Canvas`, track `LineLight`, progress arc colour keyed to grade (Excellent/Healthy → `GoldLight`; Fair → `#C98A3C`; Needs work → `#B5533C`). Centre = score in `displayMedium` Playfair. Below: three thin `LinearProgressIndicator`s for utilization / rotation / balance with their weight labels — so the composite is always decomposable in the UI, matching §5.

### 10.5 WearCalendarHeatmap

```kotlin
@Composable
fun WearCalendarHeatmap(
    grid: List<List<AnalyticsEngine.HeatDay>>,
    modifier: Modifier = Modifier,
    cell: Dp = 12.dp,
    onDayClick: ((AnalyticsEngine.HeatDay) -> Unit)? = null,
)
```
`LazyRow` of 52 week-columns, each a `Column` of 7 `Box(Modifier.size(cell).clip(RoundedCornerShape(3.dp)))`. Level→colour ramp: `0 → SurfaceAltLight #F1ECE1`, `1 → #D8C79E`, `2 → #C3A96E`, `3 → #B08A4F`, `4 → #8F6B33` (a warm gold ramp, not the usual green — keeps the ivory brand). Month labels above at the 1st-of-month columns. TalkBack: each cell merges to `"12 March, 2 items worn"`. Clickable only when `onDayClick != null`.

### 10.6 SeasonalCoverageBoard

```kotlin
@Composable
fun SeasonalCoverageBoard(
    coverage: Map<String, AnalyticsEngine.SeasonCoverage>,
    modifier: Modifier = Modifier,
)
```
One `premiumCard()` per season. Covered seasons get a gold check chip; gaps get a danger-tinted `"GAP"` pill and, when `hasCoreOutfit == false`, a `missingCore` line rendered as bypassed category emoji (`👕 👖 👟` greyed). Straight from the `SeasonCoverage` data class — no recomputation in the UI.

### 10.7 UnusedItemsPanel

```kotlin
@Composable
fun UnusedItemsPanel(
    report: AnalyticsEngine.UnusedReport,
    modifier: Modifier = Modifier,
    onItemClick: (WardrobeItem) -> Unit,
)
```
Summary row (never-worn count, dormant value) + `LazyRow` of 96 dp garment thumbnails with a `"Never worn"` care-label chip. Reuses `AsyncImage` (Coil 2.7.0) exactly as `CategoryGrid` does today.

### 10.8 Screen wiring

Fold the seven composables into the existing `AnalyticsScreen.kt` `Column` (keep `Scaffold` + `TopAppBar` unchanged). Order: `StatCard` grid (existing) → `ClosetHealthGauge` → `StyleDnaRadar` → `ColorDistributionDonut` → `CpwLeaderboard` → `SeasonalCoverageBoard` → `UnusedItemsPanel` → `WearCalendarHeatmap`. Compute everything once with `remember(allItems, events) { AnalyticsEngine.realtimeInsights(allItems) /* … */ }` and pass primitives down — keep the composables stateless so Roborazzi screenshot tests stay deterministic.
